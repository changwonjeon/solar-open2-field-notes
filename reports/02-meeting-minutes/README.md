# Task 02 성능 평가 — 다중 문서 회의록 작성

## 요약

Task 02는 Solar Open 2를 Claude Code CLI에 연결해 여러 한국어 행사 기록을 하나의 종합 회의록과 주제별 회의록으로 통합한 실험이다. 모델은 서로 다른 문서의 내용을 모아 계층적인 Markdown 문서로 재구성하고, 지정된 OKF frontmatter를 적용하는 데 성공했다.

이 사례에서 가장 강하게 확인된 능력은 **다중 문서 취합, 긴 문서 구조화, 한국어 요약, 형식 준수**다. 주요 수치와 기술 용어도 상당수 보존됐다. 반면 일부 계획과 발표 내용을 공식 결정사항처럼 재분류했고, 요약 자료를 실제 대화 기록처럼 확장한 부분이 있어 사실 기록물로 사용하려면 사람의 검수가 필요하다.

종합 평가는 다음과 같다.

| 평가 영역 | 판단 | 근거 수준 |
|---|---|---|
| 다중 문서 취합 | 양호 | 실제 산출물로 확인 |
| 한국어 구조화·가독성 | 매우 양호 | 실제 산출물로 확인 |
| OKF·Markdown 형식 준수 | 매우 양호 | 정적 검사 가능 |
| 주요 사실 보존 | 대체로 양호 | 표본 대조 결과 |
| 무누락·완전 정확성 | 입증되지 않음 | 정량 채점표 없음 |
| 추론과 원문 사실의 분리 | 보통 | 재분류·서술 확장 존재 |
| 처리 속도·비용 | 측정되지 않음 | 실행 기록 없음 |
| 타 모델 대비 우위 | 판단 불가 | 동일 조건 비교 실험 없음 |

따라서 Solar Open 2는 이 태스크에서 **실무에 활용 가능한 고품질 초안을 만드는 중상 수준의 문서 작성 성능**을 보였다. 그러나 자동 생성 결과를 검수 없이 공식 회의록으로 확정할 수준이 입증된 것은 아니다.

## 태스크와 입력 난이도

입력은 총 9개 문서였다.

- 행사 개요 1건
- 세션별 Markdown 기록 8건
- 세션 기록 중 7건은 이미 제목, 소제목, 문단 또는 불릿으로 정리된 요약 자료
- 나머지 1건은 화자 구분이 포함된 전사문에 가까운 자료

이 구성은 단순한 한 문서 요약보다 어렵다. 모델은 여러 문서에서 일정, 기술 설명, 제품 사례, 질의응답과 향후 계획을 찾아 중복을 줄이고 하나의 흐름으로 합쳐야 했다. 긴 출력에서 제목 체계와 용어 일관성을 유지해야 한다는 점도 난도를 높인다.

다만 이 실험을 “원시 음성 또는 전체 전사문을 회의록으로 변환한 평가”로 설명해서는 안 된다. 입력 대부분이 이미 사람이 읽기 좋은 형태로 정리된 2차 요약 자료였기 때문이다. 실험이 직접 입증하는 능력은 다음에 더 가깝다.

> 구조화된 요약 자료 여러 건과 일부 전사형 자료를 읽고, 이를 하나의 일관된 한국어 회의록으로 재편집하는 능력

따라서 정보 추출 난도는 원시 음성 인식이나 전체 전사문 기반 회의록 작성보다 낮고, 문서 통합과 편집의 비중이 더 크다.

## 실제 산출물

모델 실행 결과로 다음 문서가 생성됐다.

1. **종합 회의록**
   - 약 25KB, 305행
   - 행사 개요와 일정
   - 8개 세션별 요약
   - 기술 및 활용 사례 정리
   - 질의응답 요약
   - 결정사항·액션 아이템 표
   - 종합 인사이트

2. **질의응답 중심 회의록**
   - 약 11KB, 243행
   - 11개 질문 주제
   - 답변자별 내용 재구성
   - 전략 및 로드맵 표

3. **소셜 미디어용 후속 글**
   - 행사 내용과 개인적 소감을 결합한 장문 초안
   - 문서 자체에 전체 구성은 사용자가 직접 했다고 명시돼 있음

세 번째 문서는 모델 단독 성능의 증거가 아니라 **사람이 구성하고 모델이 문장 작성을 보조한 공동작성 사례**로 분류하는 편이 정확하다. 아래 성능 평가는 주로 앞의 두 회의록을 대상으로 한다.

## 세부 평가

### 1. 사실 충실도

종합 회의록은 원자료에 있던 주요 모델 규모, 컨텍스트 길이, 하드웨어 수량, 서비스 규모, 기술 명칭과 공개 일정 등을 상당수 유지했다. 8개 세션과 질의응답의 11개 주제도 결과 문서에서 모두 찾을 수 있었다. 여러 입력에 흩어진 정보를 한곳에 모으는 능력은 분명히 확인된다.

그러나 “핵심 내용을 하나도 빠뜨리지 않았다”거나 “모든 사실이 정확하다”는 결론을 내릴 근거는 부족하다.

- 원자료의 사실 목록과 정답표가 사전에 정의되지 않았다.
- 중요도 등급과 누락 판정 기준이 없다.
- 독립된 복수 채점자가 평가하지 않았다.
- 숫자, 인물·기관, 주장 귀속을 전수 검사한 기록이 없다.
- 일부 비율 표현은 원자료의 모호함을 그대로 가져와 다른 의미로 읽힐 수 있다.
- 종합 문서 말미에는 입력 수를 8건이라고 적으면서 세부 구성은 1건과 8건으로 써, 실제 합계 9건과 맞지 않는 오류가 있다.

따라서 사실 충실도는 **주요 내용 표본에서는 대체로 양호하지만 전수 정확성은 미검증**으로 평가한다.

### 2. 구조화와 한국어 문서 품질

구조화는 이 실험에서 가장 좋은 성능을 보인 영역이다.

- 전체 행사를 시간순으로 배치했다.
- 기술 발표와 활용 사례를 세션별로 분리했다.
- 긴 기술 설명을 소제목과 불릿으로 나눴다.
- 질의응답을 주제별 표로 압축했다.
- 일정, 담당, 계획을 표 형식으로 표현했다.
- 긴 문서 안에서 용어와 제목 계층을 대체로 일관되게 유지했다.

결과는 탐색하기 쉽고, 사람이 후속 편집을 시작하기 좋은 형태다. 한국어 문장도 대체로 자연스럽다. 일부 영어 표현의 혼용과 편집 흔적은 있지만 전체 이해를 방해할 정도는 아니다.

단, 결과 문서가 입력보다 훨씬 길다. 이는 단순 요약보다는 내용을 다시 풀어 쓰고 해석을 덧붙인 **확장형 편집**에 가깝다. 상세한 회의록이 목표라면 장점이지만, 압축 요약이 목적이라면 장황함과 중복을 별도로 평가해야 한다.

### 3. OKF와 형식 준수

두 핵심 회의록은 다음 요구를 충족했다.

- `type`, `title`, `description`, `tags`, `timestamp` 포함
- 모델, 상태, 실험 식별자와 입력 출처 기록
- 유효한 Markdown 제목 계층
- 표와 목록을 활용한 정보 구조화
- 선언된 입력 출처가 실제 문서와 연결됨

OKF 및 Markdown 형식 준수는 **매우 양호**로 평가할 수 있다. 이 판단은 주관적 인상뿐 아니라 문서 구조와 링크를 정적으로 검사해 확인할 수 있다.

다만 정확한 모델 revision, API endpoint, 실행 프롬프트와 생성 설정은 기록되지 않았다. 문서 형식의 provenance는 갖췄지만 모델 실행의 재현성을 보장하는 provenance는 부족하다.

### 4. 추론성 재분류와 서술 확장

모델은 원자료를 그대로 옮기지 않고 의미를 해석해 새로운 범주를 만들었다. 이 편집 능력은 읽기 좋은 결과를 만드는 데 기여했지만, 공식 기록에서는 위험 요소가 된다.

대표적인 사례는 다음과 같다.

- 발표자가 밝힌 계획, 전망, 권고를 “결정사항” 또는 “액션 아이템”으로 재분류
- 명시되지 않은 담당 주체와 기한을 문맥에서 추론해 표에 배치
- 요약 자료의 질의응답을 실제 질문과 화자별 답변 형식으로 확장
- 여러 발언을 종합해 “핵심 경쟁력”이나 “전략적 포지셔닝” 같은 평가 문구 추가
- 출처의 홍보성 주장을 독립 검증 결과처럼 보일 수 있는 문장으로 정리

이러한 내용은 전적으로 허위라고 볼 수는 없지만, 원문에 명시된 사실과 모델이 구성한 해석이 시각적으로 충분히 구분되지 않는다. 실무 적용 시에는 다음처럼 표시하는 것이 안전하다.

- `명시적 결정`과 `추정 액션 아이템` 분리
- 직접 발언, 요약, 모델 해석을 서로 다른 섹션에 배치
- 홍보성 성능 주장은 “발표자 주장”으로 귀속
- 추론한 담당자와 기한에는 `추정` 표시

### 5. 처리 시간

처리 시간은 측정되지 않았다. 다음 기록이 없어 속도와 효율을 평가할 수 없다.

- 시작·종료 시각
- 첫 응답 지연
- 전체 생성 시간
- 입력·출력 토큰
- API 비용
- 재시도 횟수
- 중간 실패 또는 컨텍스트 재주입 여부
- 사람이 수정한 시간과 범위

따라서 “빠르게 처리했다”, “한 번에 완성했다”, “비용 효율적이다” 같은 평가는 이 실험 결과에서 도출하면 안 된다.

## 모델의 기여와 실험의 한계

### 확인 가능한 기여

Solar Open 2는 적어도 다음 작업에 실질적으로 기여한 것으로 보인다.

- 여러 입력 문서의 내용을 하나의 긴 문서로 통합
- 세션과 주제 단위의 계층 구조 생성
- 원자료의 주요 수치와 기술 용어 보존
- 반복 내용을 표와 목록으로 재구성
- 한국어 장문을 일관된 문체로 작성
- OKF frontmatter와 Markdown 형식 적용

이 결과는 Solar Open 2가 한국어 업무 문서의 **초안 작성자와 편집 보조자**로 활용될 가능성을 보여준다.

### 결론을 제한하는 요소

- 단일 행사와 단일 입력 묶음만 평가했다.
- 동일 조건 반복 실행이 없어 출력 안정성을 알 수 없다.
- 대부분의 입력이 이미 구조화된 요약 자료다.
- 실행 프롬프트와 정확한 모델 revision이 보존되지 않았다.
- 생성 직후 원본과 비교한 오류 장부가 없다.
- 독립 채점이나 블라인드 평가가 없다.
- Claude, GPT 계열 또는 다른 오픈 모델과 동일 조건으로 비교하지 않았다.
- 모델 생성분과 사람의 후속 편집 범위가 완전히 분리돼 있지 않다.

따라서 이 사례를 Solar Open 2의 일반적인 회의록 성능이나 다른 모델 대비 우위를 입증하는 벤치마크로 확대 해석해서는 안 된다.

## 후속 README 오류의 취급

실험 완료 후 작업 폴더를 정리하는 과정에서 태스크 README에 일부 세션을 실제 입력과 전혀 다른 주제로 설명한 내용이 추가됐다. 예를 들어 오피스 업무 시연, 법률 AI 사례, 데스크톱 업무 자동화 세션이 파인튜닝, 음악 추천, 게임 AI 관련 세션처럼 잘못 기재됐다.

이 설명들은 다음 이유로 본 평가의 모델 성능 증거에서 제외했다.

- 핵심 회의록이 생성된 뒤 후속 문서 편집 과정에서 추가됐다.
- 원자료와 핵심 산출물에 해당 내용이 없다.
- 어떤 모델 또는 사람이 해당 문구를 작성했는지 실행 provenance가 없다.
- 원래 회의록 산출물의 사실 충실도와 분리해서 다뤄야 한다.

이 오류는 공개 문서화 품질 문제로는 반드시 수정해야 하지만, 근거 없이 Solar Open 2의 원래 회의록 생성 오류로 귀속해서도 안 된다.

## Claude 모델을 대체할 수 있는가

이 태스크는 Claude Code라는 실행 도구에 Solar Open 2를 연결해 수행됐다. 여기서 “Claude Code를 사용했다”는 사실과 “Anthropic Claude 모델이 내용을 생성했다”는 것은 구분해야 한다. Claude Code는 하네스이고, 기록상 생성 모델은 Solar Open 2로 표시돼 있다.

Solar Open 2가 Anthropic Claude 모델을 어느 정도 대체하는지는 이 실험만으로 직접 증명되지 않았다. 동일 입력과 동일 프롬프트로 실행한 Claude 결과가 없기 때문이다. 다만 이 사례는 Solar Open 2가 해당 작업을 실용적인 수준으로 완수했음을 보여주므로, 사람의 사실 검수를 전제로 한 초안 작성 범위에서는 **조건부 대체 가능**으로 평가한다.

- 입력 대부분이 이미 구조화된 한국어 요약 자료다.
- 핵심 작업은 다중 문서 요약, 재배열, Markdown 작성과 스키마 준수다.
- 특별한 Solar 전용 도구나 모델 고유 인터페이스를 사용하지 않았다.
- 결과 품질의 핵심이 고난도 계산보다 긴 문맥의 편집 일관성에 있다.

Solar Open 2가 이 문서 작업을 수행했다는 사실은 특정 공급자 모델에만 의존하지 않고 한국어 업무 문서 파이프라인을 구성할 수 있다는 장점으로 볼 수 있다. 다만 Claude 결과와의 직접 품질 차이, 처리 시간과 수정 비용은 아직 비교할 수 없다.

다만 대체 가능성을 실제로 판단하려면 다음 조건을 고정한 비교가 필요하다.

1. 동일한 9개 입력 문서
2. 동일한 시스템 지시와 사용자 프롬프트
3. 동일한 출력 스키마와 최대 길이
4. 모델별 최소 3회 반복 실행
5. 모델명을 숨긴 독립 평가
6. 사실 precision·recall, 주장 귀속, 추론 추가, 형식 오류 측정
7. 지연시간, 토큰, 비용, 사람의 수정 시간 기록

현 단계의 적절한 결론은 다음과 같다.

> Solar Open 2는 사람의 사실 검수를 전제로 한 한국어 다중 문서 회의록 초안 작성에서는 Claude 모델을 조건부로 대체할 수 있다. 다만 Claude와의 동등성이나 우위는 아직 실험적으로 확인되지 않았다.

## 최종 판단

Solar Open 2는 Task 02에서 읽기 쉽고 구조가 좋은 장문 회의록을 완성했다. 특히 이미 정리된 여러 한국어 자료를 하나로 합치고 OKF 문서로 변환하는 작업에서는 안정적인 결과를 보였다. 이는 지식 정리, 행사 기록, 내부 보고서 초안 작성에 활용할 만한 성능이다.

동시에 일부 내용은 원문 사실보다 강하게 해석됐고, 사실과 모델의 추론을 명확히 구분하지 않았다. 실행 로그와 정량 평가도 없어 정확성, 속도, 비용, 반복 안정성, 타 모델 대비 우위는 판단할 수 없다.

따라서 권장 활용 수준은 **사람이 최종 검수하는 문서 초안 및 편집 보조**다. 이 범위에서는 성능이 양호하지만, 검수 없는 공식 기록 생성기로 평가하기에는 증거가 부족하다.
